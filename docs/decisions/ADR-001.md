# ADR-001: 使用 Jetpack Compose 作为 UI 框架

- **Status**: Accepted (2026-09-16)
- **Date**: 2026-09-16
- **Deciders**: 项目维护者
- **Related ADRs**: ADR-002（图标库）、ADR-009（版本基线修正）

## Background

课表 App 的界面主体是一个高度自定义的周视图网格（星期 × 节次，课程卡片按周次/单双周条件渲染），另有导入页、课程编辑页、设置页。UI 技术有三条候选路线：

1. Jetpack Compose（Material 3）——Android 官方当前的第一优先方向；
2. 传统 View + XML 布局——存量生态最大的路线；
3. 两者混合——迁移期形态。

约束条件：项目维护者编程经验有限（教学级可读性权重高，不希望同时维护两套 UI 心智模型）；项目定位极简轻量、长期开源单人维护；2026-09 生态现状是官方新文档、新组件、Codelab 均以 Compose 为第一公民。

## Decision

采用 **Jetpack Compose（Material 3）** 作为全项目唯一 UI 技术，BOM 锚定 2026.08.00（核心模块 1.12.0），不引入任何 XML 布局作为业务界面。

补充界定：WebView 捕获页通过官方互操作 API `AndroidView` 承载系统 WebView——这是 Compose 官方提供的标准封装（Compose 包 View），属于方案内用法，**不构成"混合开发"**。项目内除该处外，不得出现 XML 布局文件承载业务界面。

## Consequences

### 正面

- 自定义周视图的实现成本显著低于 View 体系：Compose 的声明式布局 + `Canvas`/自定义 `Layout`/`LazyColumn` 组合，避免自绘 View 的手动 `invalidate` 与状态同步样板代码。
- 状态驱动刷新与数据层天然契合：仓库以 `Flow` 暴露数据（见架构文档第 8 章），Compose 直接消费，导入完成后的界面/小组件刷新无需手写事件总线。
- 生态与方向一致：官方 Material 3 组件、Navigation 3（ADR-008）、Glance 小组件全部以 Compose/Kotlin 为中心；竞品 Sleepy、Dawn Course 同为 Compose 栈，参考实现可直接读懂。
- 教学价值：单一语言（Kotlin）、单一范式（声明式）对新手的学习曲线比"XML + 命令式代码"双语言更低。

### 负面 / 代价

- 网络上存量教程与问答大量基于 View/XML，新手检索时需自行辨别适用性（缓解：本系列文档作为项目内第一参考源）。
- Compose 编译依赖 Kotlin 编译器插件，版本必须与 Kotlin 严格对齐（随 Kotlin 同版发布），因此 Kotlin 版本不能随意独升（详见 ADR-009 的版本链约束）。
- 版本连带成本：Compose 1.12 将 compileSdk 提升至 API 37，抬升了本项目的平台基线（详见 ADR-009）。
- Compose 运行时的固有体积成本（约 4–6 MB dex）无法消除，这是选择该技术栈的既定代价（APK 体积核实见架构文档 §4.5）。

### 已否决选项的代价说明

- View + XML：唯一优势是存量教程多，但该路线在官方投入方向上已属维护态；自定义周视图需自绘 View，开发与排错成本更高。
- 混合：引入两套心智模型，对单人新手项目是净负担。
