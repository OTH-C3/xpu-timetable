# ADR-002: 使用 Lucide（compose-icons）作为全项目唯一图标库

- **Status**: Accepted (2026-09-16)
- **Date**: 2026-09-16
- **Deciders**: 项目维护者
- **Related ADRs**: ADR-001（UI 框架）、ADR-009（版本基线修正）
- **特别说明**: 本 ADR 显式回应另一条曾考虑过的路线（androidx material-icons-extended / Material Symbols），证据与取舍见下。

## Background

团队级 P0 规则：全项目必须锁定**一套** SVG 图标库，禁止 emoji 图标方案，图标尺寸规范 16/20/24dp。因此图标库选型是必须给出结论的架构决策，且一旦锁定不得混用。

候选路线四条：

1. `androidx.compose.material:material-icons-core` / `material-icons-extended`（曾考虑的路线之一）；
2. Material Symbols（Google 官方新方向，曾考虑的路线之二）；
3. Lucide（社区 compose-icons 封装）；
4. Phosphor（社区图标集）。

### 证据（核实日期 2026-09-16）

**证据 1（决定性）——androidx material-icons 已被官方弃用并从 Material 3 移除。**
`androidx.compose.material.icons` 官方 API 参考页原文声明：该库不再被推荐用于在 Compose 中展示 Material 图标，Material Symbols 是新的方向，官方已**停止发布该库的更新**，且它**已从最新的 Material 3 库发布中移除**；如需继续使用必须手动添加依赖。残留版本冻结在 `material-icons-core/-extended 1.7.8`。触发变更为 Compose Material3 1.4.0 发布说明（即 BOM 2025.09.01 及之后版本生效）。
来源：developer.android.com `androidx.compose.material.icons` 包参考页；Compose Material3 1.4.0 发布说明。

**证据 2（工程实证）——主流项目已按该建议完成迁移。**
`woocommerce-android` 仓库的迁移 PR（2025-12）明确记录：移除 `material-icons-core:1.7.8`、`material-icons-core-android:1.7.8`、`material-icons-extended:1.7.8` 等全部依赖，逐个替换为从 Google Fonts 下载的 Material Symbols 图标资源；其依据即官方文档给出的建议。
来源：woocommerce-android 仓库 issue #15081（含官方引文与依赖变更清单）。

**证据 3——Google 官方推荐的替代路径是"逐图标人工下载"。**
官方指引为：在 fonts.google.com/icons 的 Android 标签页逐个下载 VectorDrawable XML 导入项目。官方同时说明停用原库的理由之一是：该库包含全部图标，会显著增加应用构建时间。
来源：developer.android.com「Compose 图形与图片 / Material 图标」文档页；官方博客与文档站转载。

**证据 4——Material Symbols 没有官方 Compose 一等库。**
社区封装（Composable Horizons 的 compose-icons，v2.2.1）同时提供 material-symbols、material-icons、lucide 等多个构件；本次仅核实到 lucide 构件（`com.composables:icons-lucide-android:2.2.1`）的精确坐标与在售状态。
来源：composables.com 文档页与 klibs.io 项目页（2026-09-16 核实）。

## Decision

**采用 Lucide，坐标 `com.composables:icons-lucide-android:2.2.1`（Android 变体，VectorDrawable XML，MIT 协议），全项目唯一图标来源。**

落地规则（规则，不可裁剪）：

1. 所有界面图标引用经 `ui/components/AppIcons.kt` 门面文件（语义名 → 资源的唯一映射），界面代码禁止直接写 `R.drawable.lucide_*`。
2. 尺寸仅 16 / 20 / 24 dp 三档，常量定义在 `ui/theme/IconSize.kt`，禁止散落魔法数字。
3. 禁止 emoji 图标；禁止引入第二个图标库。
4. 通知栏白色剪影小图（`res/drawable/ic_stat_*`）为系统要求，不属"混用"。

### 对上述替代路线的直接回应

- **`material-icons-extended` 路线：不可采纳。** 该库已被官方弃用、停止更新、并从最新 Material 3 中移除（证据 1），在 BOM 2026.08.00 下使用需要手动 pin 一个冻结在 1.7.8 的旧依赖，与"长期开源维护 + 极简轻量"定位直接冲突。且其"包含全部图标"的打包方式与官方指出的构建时间代价相悖。
- **Material Symbols 路线：是官方方向，但本项目不选其默认工程路径。** 官方路径要求逐图标人工下载 XML 并人工保持 weight/fill/grade 参数一致——这不是技术不可行，而是对单人维护项目的**持续认知负担与风格漂移风险**，且没有任何自动化机制保障一致性。若坚持 Material 视觉语言优先，替代方案为：一次性下载全套所需图标的 Material Symbols XML（统一参数）并提交仓库，同时接受后续新增图标的逐次人工维护成本。
- **两条路线二选一，不得混用**——这是 P0 规则。本 ADR 的裁决是 Lucide；若后续推翻，须新开 ADR 并说明切换成本（只影响 `AppIcons.kt` 一处，见 Consequences）。
- 需要明确的是：**Lucide 与 Material 3 组件混排不产生视觉冲突**。Lucide 为单一风格的线性描边图标（24px 网格、等宽描边），在 Material 3 界面中属常见搭配，不构成一致性缺陷。

## Consequences

### 正面

- 风格一致性由机制保障而非人工纪律：Lucide 只有一种风格，不存在 fill/outlined/rounded 变体混用的可能性。
- 接入成本最低：一个 Gradle 依赖，无注解处理器、无运行时开销，资源以 XML 交付，AS 内可直接预览。
- 体积可控：实际引用约 25–40 个图标，`shrinkResources` 开启后 XML 资源贡献 < 0.1 MB。
- 维护活跃：Composable Horizons 在 2026 年持续发版（当前 2.2.1），MIT 协议，可用于开源项目无授权顾虑。
- 可逆性高：所有引用收敛在 `AppIcons.kt`，未来切换图标库的改动面被压缩到单个文件。

### 负面 / 代价

- 维护方是第三方（Composable Horizons）而非 Google，长期存续性弱于官方库；缓解：门面文件使替换成本极低，属可接受风险。
- 非 Material 官方图标集合，若未来追求"纯 Google 设计语言"，需要走上述手工下载路线替换。
- 与 Compose 版本的兼容性需在首次构建时验证（该库要求 Kotlin ≥ 2.2、Compose ≥ 1.9，本项目 Kotlin 2.3.21 + BOM 2026.08.00 满足）。
- `R.drawable` 的资源命名在构建时以实际生成的符号名为准，`AppIcons.kt` 编写时需核对一次实际资源名（首次集成时的核对项）。

### 交叉验证提示

本 ADR 与前期设计文档可能存在结论冲突（后者曾建议 material-icons-extended / Material Symbols）。请以本 ADR 证据 1–2 为准锁定唯一图标库；冲突的解决不靠偏好取舍，而靠"官方已弃用且已从 M3 移除"这一可复现事实。
