## 三、红 P1 新发现：预览页「确认导入」按钮被系统导航栏遮挡

**这不是静态复核能发现的问题** —— 代码完全合规（Scaffold + bottomBar、文件 157 行、逻辑正确）。

### 现象

**三按钮导航**下，「确认导入」按钮**被系统导航栏压住**，只露出上沿约 1/3：

```
截图证据：docs/verify/M6/emu/04_P1缺陷_三按钮导航下确认导入被导航栏压住.png
对照证据：docs/verify/M6/emu/05_对照_手势导航下确认导入完整可点.png
```

| 导航模式 | 按钮 bounds | 表现 |
|---|---|---|
| **三按钮** | `[642,2279][791,2332]` | 被导航栏（y≥2283）压住 → **点击落到导航栏** → 进「最近任务」，导入无法完成 |
| **手势导航** | 同上（位置不变） | 完整可见可点 ✓ |

**复现**：切三按钮导航 → 走文件导入到预览页 → 截图（两次复现截图内容完全一致，确认非偶发）。

### 根因（代码确凿）

```kotlin
// MainActivity.kt:25
enableEdgeToEdge()                          // ← 开启 edge-to-edge，必须自己避让系统栏

// ImportPreviewScreen.kt:88 —— bottomBar 未加 navigationBarsPadding
bottomBar = {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .padding(horizontal = 16.dp, vertical = 12.dp),   // ← 只有普通 padding
```

**全项目零处** `navigationBarsPadding` / `systemBarsPadding` / `safeDrawingPadding`：

```
grep -rn "navigationBarsPadding\|systemBarsPadding\|safeDrawingPadding\|windowInsetsPadding" app/src/main/java
→ 空
```

**讽刺的是**，`ImportPreviewScreen.kt:6` 自己的注释写着「界面铁律：Scaffold + 自绘顶栏 statusBarsPadding」—— 顶栏避让了，**底部漏了**。

### 影响面

- **只有 `ImportPreviewScreen` 用了 `bottomBar`**（`grep bottomBar` → 仅此一处），所以**影响面就这一处**
- 影响：**三按钮导航的用户无法完成文件导入 / 二维码导入**（M6 新增的核心功能）
- 真机用的是**手势导航** → 点击正常（这解释了为什么真机验收没暴露）
- 注意 严格说手势导航下按钮**下沿仍与手势条重叠**（视觉上轻微，点击不受影响）—— 也应由 `navigationBarsPadding` 一并解决

### 建议修法（一行）

```kotlin
// ImportPreviewScreen.kt:88 的 bottomBar 内 Row
modifier = Modifier
    .fillMaxWidth()
    .navigationBarsPadding()      // ← 新增
    .padding(horizontal = 16.dp, vertical = 12.dp),

// 需补 import androidx.compose.foundation.layout.navigationBarsPadding
```

> 同时建议把这条写进项目的「界面铁律」：**顶栏 `statusBarsPadding()` / 底部固定栏 `navigationBarsPadding()` / 输入页 `imePadding()`** —— 三者缺一不可。当前注释只写了前两者中的一条。

**对象 ID 变化 = 闹钟被重新创建**，而 `origWhen` 保持一致（重排计算正确）→ `MY_PACKAGE_REPLACED` 恢复路径**生效** 是

> **一次被我自己否定的误报**：中途我做过「先 `am force-stop` 再 `install -r`」，闹钟没恢复，一度判 FAIL。
> 复查发现这是 Android 固有语义 —— **force-stop 会把应用置为 stopped state，该状态下收不到广播**（日志明确显示 `isStopped true`）。
> 解除 stopped（重新启动）后 `install -r`，闹钟正常重建。**是我的测试方法有误，不是 App 缺陷。**
