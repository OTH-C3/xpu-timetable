## 七、发现的问题

### P2：二维码「分享」在 API < 29 不可用，且注释自相矛盾

**位置**：`ui/transfer/QrShareScreen.kt:155-181`（调用点）、`:236-238`（`saveToGallery`）

**证据**：

```kotlin
// 分享按钮（:160-166）
val saved = saveToGallery(context, bitmap)
if (saved == null) {
    snackbarHostState.showSnackbar(QR_SAVE_FAIL)   // 只提示失败
} else {
    shareImage(context, saved)                     // 分享也走这个 uri
    snackbarHostState.showSnackbar(QR_SAVE_OK)
}

// :238 —— API<29 直接返回 null
if (Build.VERSION.SDK_INT < 29) return@withContext null
```

**问题**：分享**完全依赖** `saveToGallery` 的返回值。而它在 API < 29 时恒为 null → **API 26/27/28 上「分享」与「保存」两个按钮都只能弹失败**。

**但注释（`:12`、`:234`）写的是**「更低版本提示改用**分享**」—— 自相矛盾：分享本身也依赖 MediaStore，这条降级路径是空头承诺。

**影响面**：
- `minSdk = 26`（ADR-009 锁定）→ Android 8.0/8.1/9.0 是**声明支持**的设备
- **真机为 Android 16，不受影响** → 不阻断本次验收
- 文件导出（SAF `CreateDocument`，API 19+）不受影响，用户仍有替代路径

**建议修法（择一）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（真正修好）** | API<29 时写 `cacheDir` + `FileProvider.getUriForFile` 分享 | 需加 provider 声明 + `res/xml/file_paths.xml` |
| **C（诚实降级，推荐）** | API<29 时提示「当前系统版本不支持二维码分享，请改用导出课表文件」，并**修正注释** | 零成本，但功能仍缺 |

> 因影响面小（2026 年在校生用 Android 8/9 的比例极低）且有替代路径，建议按 **C** 处理，或排入后续版本按 A 修好。

### P3：`anomalies` 提示无条件添加

**位置**：`data/transfer/ScheduleCodec.kt:127-129`

```kotlin
if (activeTerm != null) {
    anomalies.add("文件学期为「${dto.term.name}」，将导入到当前学期「${activeTerm.name}」")
}
```

**问题**：只要存在激活学期就提示，**即使两个学期完全一致**（`startDate` 相同）也会提示「将导入到当前学期」。措辞可能让用户误以为学期不同。

**建议**：仅当 `activeTerm.startDate != dto.term.startDate` 时才加此提示；一致时改为中性说明或不提示。
