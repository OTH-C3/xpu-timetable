## 需求 6 的页面结构（照系统设置页截图）

```
我的
  ── 学期 ──   学期设置          >     起始日 2026-10-02 · 18 周
  ── 权限 ──   精确闹钟授权      >     已授权
  ── 数据 ──   导出课表文件            保存为 .json，可发给同学或备份
               二维码分享课表    >     生成一张二维码，对方扫码即可导入
  ── 关于 ──   关于与隐私        >     非官方校园工具 · 数据仅存本机
```

「学期设置」二级页 = 起始日（点开日期选择器）+ 总周数（− / 值 / ＋ 步进器）+ 一行
「今天是第 N 周」校正提示（起始日错了周次全错，这行让用户一眼能验）。

### 一处待确认的解读

需求原文是「把学期和总周数等功能，**分别**弄到二级页面」。我的实现是**同一个**「学期设置」
页承载「起始日 + 总周数」两者（两者都是"本学期"的属性，拆成两页要多一次进出）。
若本意是两个独立二级页，拆分成本很低（各出一个页面、根页加一行）。

## 验收中发现并修掉的真实缺陷

「我的」页的学期设置摘要曾显示为 `" · 起始日 2026-10-02 · 18 周"` —— 首部多一个分隔符。
根因：`SettingsViewModel.persist()` 创建学期成功时只更新了 `hasTerm` / `savedTick`，
**没有把新算出的学期名写回状态**，于是 `termName` 仍为空。
修法：创建分支把 `createdName` 回写进状态；同时在摘要函数里加"名字为空则不加分隔符"的第二道防线。

## 工程侧的必要动作

1. **AppNav 触门禁**：改动中它到了 **301 行**（限 300）。把返回键接线抽成
   `ui/navigation/BackKeyWiring.kt`（纯接线，与渲染无关），抽出后 **288 行**，
   再容下 M9 新增的两个目的地分支。抽出的接线经回归验证：二次返回提示、连按退出都正常。
2. **`WeekCalc.termNameOf` 提升到纯函数层**：创建学期现在有两个入口（空态 / 学期设置页），
   学期命名规则必须同源，故从 `TimetableViewModel` 提到 `WeekCalc` 并补 5 例单测。
3. **一处 Kotlin 作用域坑**：`SettingsUiState` 是顶层 data class，默认值取不到
   `SettingsViewModel.Companion` 里的常量 → 周数上下限/默认值改为文件级顶层常量。
4. **一处 Compose 参数坑**：`SettingsActionRow(title, subtitle) { ... }` 的尾随 lambda
   会被绑到最后一个参数 `showDivider: Boolean` → 必须写 `onClick = { ... }`。
