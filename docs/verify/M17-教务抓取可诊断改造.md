## 一、这次补的是哪两个盲区

0.3.0 已经把判定从「一条精确 URL 正则」改成「宽匹配 + 按响应内容确认」，但还剩两处
**会静默失败**的地方：

| # | 盲区 | 后果 |
|---|------|------|
| 1 | 主机名写死 `jwglxt.xpu.edu.cn` | 学校若把数据挪到新子域，`shouldInspect` 直接返回 false，诊断卡片**空白** |
| 2 | 结构既不是 `studentTableVms` 也不是 `kbList` | `when` 没有 else 分支，代码什么都不做，用户只看到网页正常显示 |

两种情况的共同症状都是「登录了、页面也对，就是没有导入结果」，且**没有任何线索**。

## 三、隐私边界（这块截图是要发给开发者看的）

`structuralSignature` 只返回**键名**，例如：

```
未识别 /student/for-std/course-table/print-data  [学期 147]  字段：code, msg, data
```

- 不返回值、不返回 Cookie/token、不落盘、不上传
- 扫描上限 4096 字符（键名都在开头），键名最多 8 个、单个不超过 32 字符
- 路径本身复用 `diagnosticPath`，它已经丢掉全部 query 参数

## 六、0.3.2 补：宽匹配误伤页面导航（2026-11-05 18:35）

### 现象

真机登录成功后，课表页没有渲染，屏幕上是一整页 **HTML 源码文本**。

### 根因

0.3.1 把路径关键字放宽到 `course-table`，于是登录跳转的那次**顶层文档请求**
`/student/for-std/course-table` 也被 `shouldInterceptRequest` 拦下重新代发了。
代发用 `HttpURLConnection` 只带回了响应体，**不带原响应头**；`WebResourceResponse`
拿不到 Content-Type 就兜底成 `application/json`，WebView 于是把它当 JSON 文本显示，
页面里的 JS 一次都没执行 —— 数据请求自然也不会发出，比"抓不到"更糟。

### 修法（两道防线，针对这一类而不是这一例）

| 防线 | 位置 | 判据 |
|------|------|------|
| 一 | `shouldInspect(isForMainFrame)` | 顶层导航不代发（地址栏那一次） |
| 二 | `shouldInspect(acceptHeader)` → `wantsDocument` | Accept 含 `text/html` / `application/xhtml` 即视为文档，**覆盖 iframe 里的页面**（它的 `isForMainFrame` 也是 false） |
| 兜底 | `responseContentType(serverType, body)` | 服务器没给类型时按形状猜：`<` 开头按网页、`{`/`[` 开头按 JSON，其余 text/plain |

### 教训

放宽匹配前要先想清"这条判据会不会命中**文档请求**"。代发只适合**纯数据请求**：
数据丢了表现是"没反应"，页面被代发表现是"整页报废"，两者代价不对称。
块注释里写 `*` 加 `/` 会新开一层注释 —— 本次因此编译失败一次（Kotlin 块注释可嵌套）。
