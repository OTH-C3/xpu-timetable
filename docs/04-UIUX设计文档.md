## 0. 一句话设计方向

> **以 Material 3（Material You）为骨架、以 WakeUp 的信息层级为参照、以「打开即见课表」为零妥协原则——做一个看起来像系统自带应用的课表工具，而不是一个"App"。**

三个关键词：**纯净（无一处广告/推广位）、即时（冷启动直达当前周当前节课）、秩序（高密度信息下依然一眼可辨）**。

## 1. 设计定位判断：这是「产品型」设计

在设计方法论里，设计分两种"寄存器"：

| 寄存器 | 适合 | 标杆 | 色彩策略 |
|---|---|---|---|
| **品牌型**（Brand） | 官网、落地页、作品集——设计本身就是产品 | 独特性、惊艳 | 允许饱和色占 30-60% |
| **产品型**（Product） | 工具、仪表盘、App UI——设计为功能服务 | **赢得熟悉感**（用户觉得"这 App 很靠谱"） | 中性色 70-90%，强调色一个 |

课表 App 是每天要打开多次的**工具**，属于典型的产品型寄存器。这意味着：

- **为什么不做炫技设计**：学生早上 7:50 赶着看下节课在哪个教室，此时任何装饰性的动画、大面积品牌色、花哨转场都是负资产。工具的最高境界是"感觉不到设计的存在"——就像系统自带的时钟应用。
- **为什么对标的都是"克制"的应用**：Linear、Notion、系统原生应用这类产品型标杆的共性是：中性色打底、单一强调色、信息密度高但层级清晰。课表恰好是"高密度信息网格"，与仪表盘同构。

**三轴设计刻度**（Phase 2 生成 Token 时的量化依据）：

| 刻度 | 取值 | 理由 |
|---|---|---|
| DESIGN_VARIANCE（布局个性） | **3 / 10** | 工具型应用需要可预测的对称布局。周视图是天然对称的 7 列网格，不需要非对称美学 |
| MOTION_INTENSITY（动效强度） | **3 / 10** | 只保留功能性动效：页面切换、抽屉展开、卡片点击反馈。无装饰性动画 |
| VISUAL_DENSITY（信息密度） | **7 / 10** | 课表本质是"驾驶舱"级密集信息界面——但要用层级和留白技巧消解压迫感（见第 8 章） |

## 2. 竞品调研（4 款）

调研方法：逐一分析**周视图网格处理、色彩系统、信息层级**三个维度——这正是我们项目最核心的三个设计战场。

### 2.1 Sleepy 课程表（lingion/sleepy）—— 正面标杆

**背景**：开源（GitHub），Kotlin + Jetpack Compose + Material 3 构建，与我们技术栈完全一致。无广告、本地优先、默认不联网。支持多视图、教务导入、桌面小组件（Glance）、HSV 自定义配色。

**周视图处理**（从其更新日志逆向分析，这些是踩过坑的实战经验，对我们价值极高）：
- 网格架构经历过一次重写：`BoxWithConstraints + Modifier.offset` 绝对定位，替代 `weight` 均分。**为什么**：weight 均分在课程卡片跨多节课时会产生 Round 累积误差，导致列对不齐、卡片错位。这对我们是直接的架构级提示。
- 修复过"时间栏塌缩"问题：10 节长课不能把左侧时间轴压扁，**每节课时间必须独立成行**。
- 移除了空 cell 占位符——空格子不渲染任何东西，靠网格线本身区分。

**色彩系统**：
- 课程自动配色采用「黄金角 137.5°」算法：按课程组 ID 确定性分配 HSL 色相。**为什么是黄金角**：137.5° 是无理数角度，连续分配的颜色色相差最大化，前 8-10 门课几乎不会撞色。且"确定性"意味着同一门课每次打开颜色都一样——**颜色成为课程的第二身份标识**。
- 支持用户 HSV 自定义颜色，用户选择优先于自动分配。
- 整体框架色（背景、顶栏）遵循 Material You 动态取色。

**信息层级**：课程卡片 = 课名 + 教室为主，点击进入详情。主界面只放"看课表"必需的信息。

**对我们的启示**：5/5 它证明了「Compose + M3 + 课表」这条路走得通，且它踩过的坑（weight 误差、时间栏塌缩、小组件双引擎刷新）我们可以直接绕开。

### 2.2 WakeUp课程表（wakeup.fun）—— 信息层级的教科书

**背景**：闭源免费，体积小（老版本 5.7MB）、启动极快、无广告无后台。大学生群体口碑极佳，是"极简课表"品类的定义者。

**周视图处理**：
- 主界面 = 顶部状态区 + 日期栏 + 左侧时间轴 + 周网格，结构清晰，没有一个多余的像素。
- **日期栏的"淡化"设计**：非当前周、非今天的日期自动弱化显示。这是一个成本极低但体验极佳的技巧——用户永远知道"今天在哪"。
- **"非本周"提示 + 点击快速回到当前周**：浏览其他周时给一条明确的"回家"路径。
- 周数轴：用一根进度条式的滑竿展示"当前周在整个学期中的位置"，既是信息也是操作（点按跳周）。

**色彩系统**：课程颜色用户可自定义（颜色、字体、背景），但**默认配色克制**，主色调柔和温暖，长时间看不疲劳。

**信息层级**：功能入口高度收敛——右上角仅 4 个按钮（添加/导入/导出/更多），其余全部收进底部功能面板。**为什么重要**：这是"渐进披露"（Progressive Disclosure）的典范——常用功能一触可达，低频功能收起来不占注意力。

**对我们的启示**：5/5 直接借鉴其"顶部状态区 + 淡化非今日 + 快速回本周"三件套，以及功能入口收敛策略。

### 2.3 Dawn Course（破晓课程表）—— 工程参照

**背景**：开源（GPL-3.0），Kotlin + Compose + Material 3 + MVVM + Clean Architecture，Glance 小组件，适配正方/强智/青果教务。定位"本地优先、数据主权"，与我们的价值观同源。

**对我们的启示**：4.5/5 主要价值在**工程架构与设计的配合方式**（多模块、feature 解耦对设计系统的影响：主题必须放在 core/ui 层供所有 feature 复用——这决定了我们 Phase 2 的 Token 文件位置）。其 UI 走标准 M3 路线，浅深色主题齐备，验证了 M3 默认方案对课表场景的可用性，但视觉辨识度一般。

### 2.4 超级课程表 —— 反面教材

**背景**：下载量最大的课表 App（1802 万+），但用户差评集中在：**广告（开屏广告、摇一摇误触跳转、应用间弹广告）、强制注册、冗余功能（社交"下课聊"、校花校草排行榜、二手交易）**。用户原话："本来用就只要一个课表，做这么多与课表无关的拓展服务实在离谱"。

**它错在哪（设计视角的解构）**：
- **商业目标压倒了用户目标**：每个广告位、每个社区入口都在抢夺"看课表"这个核心任务的注意力。
- **信息层级被破坏**：打开 App 先看 3-4 秒广告才能见到课表——违反了课表 App 的第一要义"打开即见"。
- **权限与信任**：手机号注册 + 定位权限，用户感知到的是"被索取"而非"被服务"。

**对我们的启示**：5/5（负向）——它是我们项目立项理由的最佳注脚。每当我们想加一个功能/入口时，先问一句："超级课程表会加吗？"如果答案是会，再问"它和'今天下课去哪'有关吗？"

### 2.5 竞品调研总结表

| 维度 | Sleepy | WakeUp | Dawn | 超级课程表 | **我们的选择** |
|---|---|---|---|---|---|
| 周视图网格 | 绝对定位架构（避坑） | 淡化非今日 + 周数轴 | 标准 M3 网格 | 广告穿插破坏网格 | **Sleepy 架构 + WakeUp 层级技巧** |
| 色彩系统 | M3 动态取色 + 黄金角课程色 | 克制默认色 + 用户自定义 | 标准 M3 | 花哨、商业化 | **动态取色管框架 + 固定调色板管课程（双层分离，见 §5.4）** |
| 信息层级 | 简洁 | 渐进披露典范 | 标准 | 混乱 | **WakeUp 模式：4 个主入口 + 收纳面板** |
| 信任感 | 高（本地优先） | 高（无后台） | 高（开源） | 低 | **开源 + 本地优先 + 最小权限** |

## 3. 对标品牌与设计语言选型

### 3.1 选型结论

**设计语言：Material 3（Material You）**，即 Jetpack Compose 的原生设计体系，启用 Android 12+ 动态取色。

**对标品牌**（按影响权重排序）：

| 对标对象 | 借鉴什么 |
|---|---|
| **Sleepy 课程表** | 整体路线：Compose + M3 的课表实现范式、黄金角课程配色算法 |
| **WakeUp 课程表** | 信息层级：顶部状态区、日期淡化、功能收纳、周数轴 |
| **Google 系统应用（时钟/日历）** | 终极形态：让 App 看起来像系统的一部分——切换系统深浅色时无缝跟随，用动态取色融入用户壁纸 |

### 3.2 为什么是 Material 3 而不是自定义设计语言

这是本项目最重要的设计决策，理由有四条：

1. **技术栈已锁定 Compose + M3**（架构师 Spec），选 M3 等于"顺着纹理砍柴"。M3 组件（TopAppBar、FAB、BottomSheet、Snackbar）开箱即用，我们可以把全部精力投入最难的周视图网格，而不是重新发明按钮和对话框。**为什么这点对发起人特别重要**：编程经验有限的团队，每自定义一个组件都是未来的维护债务。
2. **动态取色是 Android 生态的"信任信号"**。Android 12+ 用户换壁纸时，跟随系统变色的应用会被潜意识识别为"正规军"。iOS 上没有这种机制，但 Android 上放弃了动态取色，等于主动放弃了平台红利。
3. **深浅色主题是 M3 的一等公民**。`lightColorScheme()` / `darkColorScheme()` + `isSystemInDarkTheme()`，一套 Token 自动生成两套主题，符合我们"深浅色都要支持"的需求。
4. **反面排除**：自定义设计语言（如某品牌的卡片阴影风）意味着每个组件手写样式、深浅色手动调两遍、无障碍对比度自己验——对一个开源、轻量、维护者经验有限的项目，这是不可承受之重。

### 3.3 「极简美观」的具体定义

"极简美观"如果不可度量，就会沦为口号。以下是本项目对它的**可验收定义**：

**极简 =**
- 主界面（周视图）上，除课表内容外的可点击元素 ≤ 6 个；
- 从冷启动到看清"下节课是什么" ≤ 1.5 秒（无开屏广告/引导页拦截）；
- 任何界面禁止出现：广告、运营位、推广 banner、评分弹窗、"分享给同学"浮层；
- 设置项 ≤ 15 个，每个设置项都能在 5 秒内被理解。

**美观 =**
- 遵循一套完整 Design Token（Phase 2 产出），全 App 无一处硬编码颜色/间距；
- 深浅色两套主题下，正文对比度均 ≥ 4.5:1（WCAG AA）；
- 课程色块在两套主题下均可辨识且不刺眼（具体见 §5.4 的双层色彩策略）；
- 动效只做功能性反馈（150-300ms），无一超过 400ms，全部尊重系统"减弱动态效果"设置。

## 4. 配色方向

### 4.1 总体结构：双层色彩系统（本项目最重要的色彩决策）

课表 App 的色彩问题有一个独特矛盾：**界面框架色**（背景、顶栏、按钮）需要"融入系统、克制中性"；而**课程区分色**（十几门课各占一格）需要"足够鲜艳、彼此可辨"。用一套体系同时满足两者必然顾此失彼。

**解决方案：色彩系统分两层，各自独立——**

```
┌─────────────────────────────────────────────┐
│ 第一层：框架色（Chrome Layer）                │
│ 作用域：背景、顶栏、侧边抽屉、按钮、对话框     │
│ 来源：Material You 动态取色（Android 12+）    │
│       ↓ 无动态色时 fallback 到静态品牌色      │
│ 特性：跟随系统壁纸/深浅色变化，极度克制        │
├─────────────────────────────────────────────┤
│ 第二层：课程色（Course Layer）                │
│ 作用域：周视图/日视图中的课程卡片、课程详情    │
│ 来源：固定调色板（12 色，黄金角预生成）       │
│ 特性：**绝不跟随动态取色**，保证课程身份稳定   │
└─────────────────────────────────────────────┘
```

**为什么课程色不能跟随动态取色**（这是 Sleepy 实践验证过的结论）：
1. 动态取色从壁纸提取的调色板只有 5 个色调系列（hue），而一学期可能有 10+ 门课，必然撞色；
2. 壁纸一换，所有课的颜色全变——用户建立的"高数=蓝色"肌肉记忆瞬间作废，**颜色作为课程第二身份标识的价值归零**；
3. 深浅色主题下动态色的表现不可控（可能提取出对比度不足的组合），固定调色板可以逐一验证。

### 4.2 框架色：动态取色的取舍结论

**取舍结论：采用。** 具体策略：

- Android 12+（SDK 31+）：`dynamicLightColorScheme(context)` / `dynamicDarkColorScheme(context)` 一行启用；
- Android 8-11（我们 minSdk 覆盖的范围）：fallback 到静态品牌色方案；
- **设置里提供开关**："跟随系统取色"默认开，可关闭改用品牌色。**为什么给开关**：动态取色的结果取决于用户壁纸，少数壁纸会提取出很怪的颜色（如全黑壁纸提出灰蒙蒙的调子），给用户退路是产品型应用的基本修养。

**静态品牌色方向**（fallback 方案 + 关闭动态色时使用）：
- 主色（Primary）：**蓝色系**，方向为 M3 Tonal Palette 中的 Blue 色系（Phase 2 将给出精确色值，大致区间为 `#0B57D0` 附近的 Google Blue 体系）。**为什么选蓝**：① 教育/工具品类的心智色（冷静、可信、无性别倾向）；② 与"西安工程大学"的校徽蓝色系天然兼容（校徽为蓝色调）；③ 避开了"默认 Indigo `#6366F1`"这一被 AI 生成设计用滥的首罪色值（我们用更深的 Google Blue 体系，明度/饱和度都不同）；
- 中性色：M3 的 Neutral + Neutral Variant 色调系列（浅色主题背景约 `#FDFBFF` 系、深色主题约 `#1A1B21` 系——**绝不是纯黑 `#000` / 纯白 `#fff`**，M3 的 tonal 体系自带微妙的蓝色调偏移，深色下用亮度递进表达层级而非阴影）；
- 强调色使用纪律：**每屏 ≤ 2 处可见的主色使用**（如顶栏"回到本周"按钮 + FAB），其余一律中性色。课表主界面色彩的主角是课程卡片，框架必须退后。

### 4.3 深浅两套主题的思路

| 维度 | 浅色主题 | 深色主题 |
|---|---|---|
| 背景 | 近白（tonal 98-99），微冷调 | 近黑（tonal 6-10），**不用纯黑** |
| 层级表达 | 表面色深浅递进 + 细边框 | **亮度递进**（背景→卡片→浮层逐级 +3~5% 亮度），不用重阴影 |
| 课程卡片 | 该课程色的 **container 色**（浅色、低饱和版本） | 该课程色的 **dark container 色**（同一色相、低明度版本） |
| 边框 | 1px 细边框（tonal 90 系） | 半透明白描边 `rgba(255,255,255,0.08)` 或无边框靠亮度分层 |
| 正文对比度 | ≥ 4.5:1 | ≥ 4.5:1（深色下重点验算，禁用 tonal 60 以下文字色） |

**为什么课程卡片用 container 色而不用主色**：M3 的 Tonal Palette 机制中，每种色相都有 13 档明度。浅色主题下卡片用第 90-95 档（很浅的色底），深色主题用第 10-30 档（很深的同色相底）。这样同一门课在两套主题下**色相一致（身份不变）**，但明度适配各自主题（都不刺眼）。这是 M3 送给课表 App 的礼物，Sleepy 也正是这么做的。

**深色主题优先级提示**：用户 IDE 常驻深色 + 学生夜间使用普遍 → 深色主题不是浅色的"移植"，而是同等地位的公民。Phase 2 验证对比度时两套主题都过一遍。

### 4.4 课程色板（方向性定义，精确色值 Phase 2 冻结）

- **12 色固定调色板**，色相按黄金角 137.5° 预生成分布（红→绿→蓝→紫环状铺开）；
- 饱和度/明度统一约束在"低-中"区间（浅色主题下饱和度约 50-70%、明度 90+；深色主题反之）——**为什么**：饱和度拉满的色块在 7×12 的网格里会形成视觉噪音风暴，互相打架；
- 分配算法：按课程名规范化分组后，以组 ID × 黄金角确定性分配（Sleepy 已验证此方案的稳定性——同一门课永远同色，与数据库行号无关）；
- 用户可覆盖：编辑课程时提供色板选择（12 选 1），用户选择优先级最高。

## 5. 字体方案

### 5.1 结论

| 用途 | 字体方案 | 说明 |
|---|---|---|
| 界面正文/标题（中文为主） | **系统默认字体栈**（Android 上即 Roboto + 各厂商中文字体 MiSans / OPPO Sans / HarmonyOS Sans / Noto Sans CJK） | 不打包中文字体 |
| 数字/时间/周数 | **Roboto Mono（打包 Latin 子集，约 50-100KB）**，用于时间轴、节次号、周数、"08:00-09:40" 等时间串 | 等宽数字 |
| App 名称等品牌展示场景 | 暂用系统字体 Medium/SemiBold 字重，不引入展示字体 | 极简定位下品牌字重即可 |

### 5.2 为什么中文不打包自定义字体（一个反直觉但正确的决策）

直觉上"极简美观"似乎该配一款好看的中文字体，但打包中文字体的代价是：**一款全量中文字体 3-8MB**，我们整个 App 的目标体积可能只有 15MB 左右——一款字体吃掉 1/3 的体积，与"轻量"的核心定位直接冲突。

而 Android 中文生态的现实是：**2020 年后的国产 ROM（MIUI/ColorOS/鸿蒙等）自带的中文默认字体质量非常高**（MiSans、OPPO Sans 都是重金委托设计的现代无衬线体），它们的"丑"时代已经结束了。系统字体还有三个附赠优势：

1. 跟随系统字体设置（老年模式/超大字体无障碍场景零成本支持）；
2. 内存零额外占用，启动更快；
3. 与系统应用视觉一致——正好强化我们"像系统自带应用"的定位。

**注意**：这不等于"默认系统字体直出"的偷懒。我们要做的是**在系统字体之上建立严格的排版 Token 体系**（M3 Type Scale），层级全部自定义锁定：

| 层级 | 字号/字重 | 用途 |
|---|---|---|
| displaySmall | 36sp / 400 | （预留给开学周等大数字场景） |
| headlineSmall | 24sp / 400 | 课程详情页标题 |
| titleLarge | 22sp / 400 | 页面标题 |
| titleMedium | 16sp / 500 | 课程卡片内课名 |
| bodyMedium | 14sp / 400 | 课程卡片内教室/教师、正文 |
| labelMedium | 12sp / 500 | 时间轴节次、周次徽章 |
| **课程卡片课名** | **13sp / 500**（自定义层级） | 7 列网格内小屏也能放下 6 个汉字 |
| **课程卡片次要信息** | **11sp / 400**（自定义层级，全 App 最小字号红线） | 教室号，低于 11sp 一律不允许 |

### 5.3 数字为什么必须等宽

时间轴（`08:00` / `10:00`）和周数（第 1-20 周）是课表的高频数字场景。比例字体（默认 Roboto）的数字宽度不一（1 窄 0 宽），竖向排列的时间轴会左右抖动，密集场景下严重影响扫描效率。等宽字体让所有数字对齐成整齐的列——这是"驾驶舱"界面的基本纪律。Roboto Mono 只含 Latin 字符，子集化后极小，性价比极高。

## 6. 图标库（已裁决锁定：Lucide）

> **本节修订说明（2026-09-16，团队领导裁决）**：本节初版建议 Material Symbols + `androidx.compose.material.icons` 路线。经架构师 ADR-002 交叉验证，该技术路径已被官方废弃（`androidx.compose.material.icons` 不再推荐使用、停止发布更新、已从最新 Material 3 发布中移除，残留版本冻结 1.7.8；官方替代路径为"逐图标从 Google Fonts 人工下载 XML"，对单人维护项目构成持续认知负担与风格漂移风险）。**本方向文档据此改判：全项目唯一图标库 = Lucide**，详见 `docs/decisions/ADR-002.md`。保留的审美关切已如实改写至 §6.3。

### 6.1 结论（锁定）

**全项目唯一图标库：Lucide（`com.composables:icons-lucide-android:2.2.1`，MIT 协议）。**
**风格规格：24px 设计网格、2px 等宽描边、单一线性风格（无填充/描边变体之分）。**
**交付形态：Android 变体以静态 VectorDrawable XML 交付（编译期资源，无运行时桥接层）。**
**引用纪律：全部引用收敛到 `ui/components/AppIcons.kt` 门面文件（语义名 → 资源的唯一映射），界面代码禁止直写 `R.drawable.lucide_*`。**

### 6.2 为什么是 Lucide（四条理由）

1. **风格一致性由机制保障，而非人工纪律**：Lucide 只有一种风格（线性描边），**结构上不存在** fill / outlined / rounded 变体混用的可能性。Material Symbols 体系恰恰相反——FILL/WGHT/GRAD 三轴可调意味着"每次都得记得统一参数"，官方推荐的落地方式又是逐图标人工下载 XML，一旦某次忘改参数就会出现图标粗细不一的风格漂移。对单人维护的开源项目，"不可能做错"优于"记得别做错"。
2. **接入成本最低且可逆性最高**：一个 Gradle 依赖即用，无注解处理器、无运行时开销，资源是编译期 XML（AS 内可直接预览）。且所有引用收敛在 `AppIcons.kt` 单文件——未来若要更换图标库，改动面被压缩到一个文件，这是架构上的"保险"。
3. **体积可控，契合轻量定位**：本项目实际需要约 25-40 个图标，开启 `shrinkResources` 后 XML 资源贡献 < 0.1MB。对比 Material Symbols 手工下载路线虽也只需少量图标，但每次新增图标都要人工走一遍下载-改参数-导入流程。
4. **语义覆盖满足本项目全部场景**：导入（download / cloud-download）、添加（plus）、课表（calendar-days / layout-grid）、提醒（bell / alarm-clock）、设置（settings）、周次跳转（chevron-left / chevron-right）、教室（map-pin / door-open）、教师（user / users）、编辑（pencil）、删除（trash-2）、返回（arrow-left）、关闭（x）等，覆盖度充分。

> **初版"官方生态零摩擦"论点为何不再成立**：初版把"官方 API 直接可用"列为第一优势，前提是 `androidx.compose.material.icons` 仍受官方维护。该前提已被推翻——使用它反而需要手动 pin 一个冻结在 1.7.8 的旧依赖，与"长期开源维护 + 极简轻量"定位直接冲突。依赖一个已废弃的库，其摩擦成本远高于引入一个活跃维护的第三方 XML 资源库。

### 6.3 审美关切的如实交代（原"线条与 M3 密度匹配度"）

初版曾担心"第三方图标与 M3 组件的线条粗细/视觉密度打架"。如实修订如下：

- **"变体混用"这一具体风险已消除**：该风险的来源是多变体体系（Material Symbols 的 fill/outlined/rounded），Lucide 单风格不产生此问题。ADR-002 亦明确：Lucide 与 Material 3 组件混排在业界属常见搭配，不构成一致性缺陷。
- **保留为 Phase 2 视觉走查项**：Lucide 为 24px 网格 / 2px 等宽描边，Material 3 图标体系为 24px 网格 / 约 2dp（随 optical size 微调）描边——两者在**极端字号下的视觉权重**（如 16dp 行内图标与 M3 组件的并排观感）需在 Phase 2 出真机视觉走查：具体检查项为「16dp Lucide 图标与 M3 TextField/Chip 内文字并排时的视觉重量是否失衡」。若发现失衡，处理手段是局部调整图标尺寸档位（16→18dp 或在 16dp 档内接受），**而非更换图标库**（P0：全项目单一图标库）。

### 6.4 尺寸与用法纪律（全项目锁定）

- **16dp**：行内图标（文字旁的辅助图标，如教室名旁的 map-pin）；
- **20dp**：按钮/BottomSheet 项内图标；
- **24dp**：独立图标（TopAppBar 动作、FAB、导航）；
- 尺寸常量统一定义在 `ui/theme/IconSize.kt`，禁止散落魔法数字；
- **不表达"选中/未选中"的双态视觉**（Lucide 无填充变体）：选中态改用**主色着色 + 背景容器形状**表达（如 SegmentedButton 的 M3 原生选中态），不依赖图标本身变形；
- 通知栏白色剪影小图（`res/drawable/ic_stat_*`）为 Android 系统强制要求，不计入"混用"（ADR-002 规则 4）；
- **全项目禁止 emoji 出现在任何 UI 功能位置**——图标一律来自 Lucide。课程卡片内如果空间不足，宁可省略图标也不能用 emoji 顶替；**禁止引入第二个图标库**。

## 7. 周视图网格可读性设计原则（核心章节）

周视图是整个 App 的灵魂界面，也是设计难度最高的地方：**7 天 × 最多 12 节 × 每格"课名(课程编号)(任课教师)(上课周,上课教室)"五类信息**，要在 6 英寸屏幕上保持"一眼可辨"。以下是八条设计原则，每条都标注了"为什么"。

### 7.1 结构原则：时间轴 + 7 列网格 + 双向滚动

```
┌──────┬───┬───┬───┬───┬───┬───┬───┐
│ 周次  │ 一 │ 二 │ 三 │ 四 │ 五 │ 六 │ 日 │ ← 日期栏（粘性，吸顶）
├──────┼───┼───┼───┼───┼───┼───┼───┤
│ 1    │███│   │███│███│   │   │   │
│08:00 │███│   │███│███│   │   │   │ ← 左侧时间轴（粘性，吸左）
├──────┼───┼───┼───┼───┼───┼───┼───┤
│ 2    │███│███│███│███│   │███│   │
│10:00 │███│███│███│███│   │███│   │ ← 课程卡片跨节时纵向合并
└──────┴───┴───┴───┴───┴───┴───┴───┘
     （纵向：节次少时可全屏展示；多时可上下滚动）
     （横向：左右滑动切换周次——这是课表用户的肌肉记忆）
```

- **左轴 + 顶栏必须粘性固定**（sticky）：滚动查看第 8-12 节课时，时间和星期永远可见。**为什么**：脱离坐标轴的色块没有任何意义，"第 3 节"和"星期三"是课程卡片存在的参照系。
- **左右滑动 = 切周**，不做横向滚动（7 列必须同屏完整显示）。**为什么**：如果横向要滚动，"今天有几门课"需要滚动两次才能看全，破坏全局视野。7 列在主流 360dp 宽屏幕上每列约 44dp，恰好放得下 11sp 的教室号——这个约束反过来定义了我们的字号红线。
- **网格实现采用绝对定位**（`BoxWithConstraints` + offset 计算卡片位置），不用 weight 均分。这是 Sleepy 用血泪验证的架构：weight 的 Round 累积误差会让跨节卡片与时间轴错位。

### 7.2 信息层级原则：卡片内三级信息分层

课程卡片空间极其有限（约 44dp 宽 × 每节 56-64dp 高），五类信息不可能全塞进卡片。**分层策略：卡片显示 2 级，其余进详情页。**

| 层级 | 内容 | 视觉处理 | 优先级逻辑 |
|---|---|---|---|
| 第一级 | **课程名** | 13sp / 500 字重，卡片内 onContainer 深色 | 永远最优先，跨行截断显示 |
| 第二级 | **教室** | 11sp / 400，同色但透明度略低（仍保证 ≥4.5:1） | "下节课在哪"是第二高频问题 |
| 第三级 | 教师、上课周、课程编号 | **不进卡片**，点击卡片进详情页/底部弹层展示 | 赶时间时没人看教师名 |

**为什么课名 > 教室 > 其他**：调研课表 App 的真实使用场景，频率排序是——"我现在有没有课"（看色块本身）→ "下节什么课"（课名）→ "在哪个教室"（教室）→ "谁教的/第几周上"（详情）。层级设计服从使用频率，而不是服从数据完整性。

**单双周/周次的表达**：卡片右上角放一个极小的周次标记（如 `1-16` 或单/双），仅当课程**不是全学期**时显示。全学期课程零标记——**默认情况零噪音**。

### 7.3 色彩原则：色块即身份，透明度即状态

- **有课 = 色块**：课程卡片用该课程的 container 色填充（不是彩色边框、不是左侧彩条）。**为什么用整块填充而非描边**：在 44dp 宽的格子里，描边方案会损失 2×2dp 的有效面积且辨识距离短；整块填充在 30cm 视距外即可完成"这门课我有"的模式识别——颜色是网格里最快的通信通道。
- **非本周课程 = 降透明度**（约 35-45% 透明度叠加灰化）：单双周课程不在本周时仍显示幽灵块。**为什么显示幽灵块而不是完全不显示**：学生需要知道"单周这格有课，双周没有"，这是选课和自习安排的依据。幽灵块给的是"影子信息"。
- **今日列 = 微妙高亮**：日期栏中"今天"用主色小圆点/圆形背景标记（每屏 ≤2 处主色纪律的一处），网格列本身**不加背景色**——列背景会与课程色块打架。

### 7.4 间距与密度原则：用 2-3dp 缝隙换呼吸感

- 卡片与网格线之间保留 **2-3dp** 间隙（卡片不顶满格子）。**为什么**：这是高密度界面里性价比最高的留白——1dp 的缝隙就能让相邻色块"分家"，视觉压迫感显著下降，而空间代价几乎为零。
- 卡片圆角 **8dp（radius-md）**，不超过 12dp——工具型应用的克制圆角，过度圆角（16dp+）会浪费四角空间且显得"软糯"。
- 时间轴列宽约 32-36dp（够放 `08:00` 等宽字体即可），把一切宽度让给课程列。

### 7.5 空白格子原则：什么都不画

- 空白时段**不渲染任何占位元素**（无灰块、无虚线框）。**为什么**：课表的"空"本身就是信息（"这个时段我自由"），加占位符等于把信号淹没在噪音里。空白就是空白。
- 唯一例外：空课表（整学期无课）需要 Empty 状态引导——"还没有课程，去导入教务课表"+ 导入按钮。这是 5 态覆盖里 Empty 态的要求。

### 7.6 今日场景原则：为"早上 7:50 的 10 秒"设计

课表 App 最高价值的 10 秒钟是：早八课前 10 分钟，学生睡眼惺忪掏出手机。为此：

- **打开 App 自动定位当前周**（即使上次浏览的是第 8 周）；
- 顶部状态区常驻"回到本周"按钮（WakeUp 模式）——用户翻去别的周后，一键回家；
- **当前正在上的课高亮描边**（当前时间落在课程起止内时，卡片加 2dp onContainer 描边）——这是全 App 唯一一处"正在发生"的动态状态；
- 桌面小组件直接展示"今日剩余课程"列表，很多用户根本不需要打开 App。

### 7.7 节次适配原则：学校作息是变量

西安工程大学不同校区/学期的节次表可能不同（金花/临潼），周视图设计上：

- 节次数 **可配置**（8/10/12 节），时间轴高度按屏幕高度自适应：全屏高度 ÷ 节数 = 每节高度，但**设下限**（约 48dp），低于下限转入纵向滚动模式；
- 上午/下午/晚间之间画**极淡的分隔线或 4dp 空隙**——午休/晚餐是天然的认知断点，视觉上承认它。

### 7.8 触摸原则：卡片是入口不是终点

- 点击课程卡片 → 打开课程详情（BottomSheet，从底部弹出——符合 Material 3 交互规范，拇指友好）；
- 卡片自身**可点击区域 ≥ 44dp 高**：单节卡片高约 56dp 天然达标；但注意课程名等文字区域整体可点，不需要精确点中文字。

### 7.9 小结：可读性优先级总表

当设计实现发生冲突时，按以下优先级裁决（1 最高）：

1. 课名可读（截断但不换行成灾）
2. 时间轴/日期栏参照系常驻（sticky）
3. 颜色身份稳定（同课同色，深浅主题同色相）
4. 今日定位清晰（回到本周 ≤1 次点击）
5. 空白保持空白
6. 次要信息收纳（教师/周次进详情）
7. 动画（最后考虑，能减则减）

## 8. 动效原则

| 场景 | 时长 | 说明 |
|---|---|---|
| 周切换（横向滑动） | 跟手拖拽 + 松手 200ms | 用 `HorizontalPager`，跟手优先——课表滑动必须"物理直觉" |
| 卡片按压反馈 | 50-100ms | 轻微缩放（0.97）或涟漪 |
| BottomSheet 弹出 | 250ms | M3 标准 spring 动画 |
| 页面切换 | 200-300ms | 淡入淡出 + 微位移即可，**禁止花式转场** |
| 主题切换（深浅色） | 跟随系统行为 | 无需自定义 |

- 全部动效尊重 `prefers-reduced-motion` 对应的 Android 无障碍设置（关闭"移除动画"时才播放）；
- **禁止**：加载骨架屏的闪光动画、课程卡片的入场逐个动画、任何超过 400ms 的动画、弹跳缓动。

**为什么动效预算这么抠**：课表是"每天 10+ 次短暂访问"的应用，任何超过 200ms 的非必要延迟乘以使用频次都是显著的体验负债。速度本身就是极简美学的一部分。

## 9. 无障碍基线（Phase 1 定原则，Phase 2 出数值）

- 正文对比度 ≥ 4.5:1，大字/图形 ≥ 3:1，**深浅两套主题分别验算**；
- 所有交互元素触摸目标 ≥ 48×48dp（Material 3 推荐 48dp，高于 WCAG 的 44dp）；
- 图标按钮必须有 `contentDescription`（如"回到本周"）；
- **课程颜色不承担唯一信息通道**：色块上永远有课名文字；单双周用文字标记（"单"/"双"）而非仅颜色区分——色盲用户（男性约 8%）不可忽略；
- 支持系统字体放大（sp 单位天然支持，布局需在 1.3x 字体缩放下验证不破版）；
- TalkBack 支持：课程卡片朗读顺序为"星期 → 节次 → 课名 → 教室"。

---

## 10. Do's & Don'ts（本项目的红线清单）

### Do's

1. 全部颜色/间距/字号/圆角走 Design Token（Phase 2 冻结），代码中禁止裸写 hex/dp/sp 魔法值；
2. 深浅色主题双轨验证，每个颜色 Token 两套值；
3. 图标只用 Lucide 一套（`com.composables:icons-lucide-android:2.2.1`，24px 网格 / 2px 等宽描边），经 `AppIcons.kt` 门面引用，尺寸锁定 16/20/24dp（见 §6、ADR-002）；
4. 空状态（Empty）必须给引导和入口，加载态（Loading）用静态占位不用闪烁动画；
5. 错误信息说人话："教务系统连不上，请检查校园网或稍后再试"而不是"Error: timeout"；
6. 每个设计决策在 PR/commit 里能回答"为什么"。

### Don'ts

1. **禁止任何 emoji 出现在 UI 功能位置**（P0）；
2. **禁止紫色→粉色渐变**及任何 Indigo→Pink 渐变组合（P0）——本项目当前配色方案中不存在渐变元素，未来加渐变须走同色系深浅（如 `#0B57D0 → #0842A0`）并过设计评审；
3. 禁止开屏页、引导轮播、评分弹窗、分享浮层——打开即见课表（P0）；
4. 禁止纯黑 `#000000` / 纯白 `#FFFFFF` 直接作为背景/文字色（M3 tonal 体系天然规避）；
5. 禁止"彩色左边框卡片"这一 AI 模板特征（课程卡片是整块 container 色填充，见 §7.3）；
6. 禁止虚构数据填充设计稿/截图——展示课表必须用真实感课程（如"高等数学A2(理工)002 张伟 1-16周 A-302"，禁止"课程一/课程二"这种占位）；
7. 禁止超过 5 个顶级导航入口——我们只需要：周视图（首页）、周次/视图切换、设置，三件套足够。

## 11. 给 Phase 2 的移交清单

本方向文档冻结后，Phase 2（设计系统产出）需要交付：

1. `design-system/MASTER.md` —— 按 9 节标准模板（视觉主题/色彩/排版/组件/布局/深度/守则/响应式/实现指南）落盘全部结论；
2. `design-tokens.json` + `design-tokens.css` —— 四层 Token 架构（A1-identity / A2-structure / B-slot / C-extension）：
   - A1：两套完整 M3 ColorScheme（浅/深）的精确色值 + 12 色课程调色板（每色含 light-container / dark-container / on-container 三值）；
   - A2：间距（4dp 网格）、圆角（sm 4 / md 8 / lg 12）、字号阶梯（M3 Type Scale + 两条课程卡片自定义层级）；
   - B：组件级 Token（课程卡片、时间轴、日期栏、周次徽章的具体映射）；
   - C：西安工程大学专属扩展（如校徽蓝的品牌色对齐、金花/临潼校区标签色）；
3. 各页面设计说明与状态矩阵（Default/Hover-按压/Focus/Disabled/Loading/Empty/Error/Success/Edge 九态），覆盖：周视图 / 日视图 / 课程详情 / 导入流程（含 WebView 授权登录态）/ 设置 / 小组件预览 / **课前提醒（三条子项，见下）** / **手动编辑（新增与编辑课程，见下）**；
4. **【补充·课前提醒界面】** 本次新增移交项：
   - **通知渠道方向**（Android 8+ NotificationChannel）：区分渠道并按渠道独立开关——建议「课前提醒」主渠道 + 「课表变更/导入结果」信息渠道两条，用户可在系统设置里单独关掉模板通知而不影响上课提醒；
   - **通知样式方向**：用标准通知布局（大标题=课程名，副标题=时间+教室，行内动作=「稍后提醒 / 查看课表」），不使用自定义 RemoteViews 复杂布局（维护成本与系统版本适配风险）；通知栏小图用系统要求的白色剪影 `ic_stat_*`；
   - **通知权限引导流程的 UI**：Android 13+ 需运行时权限（POST_NOTIFICATIONS）。引导原则——**不在首次冷启动弹权限**（会与"打开即见课表"冲突且拒绝率高），而是"用户首次完成课表导入/手动添加课程后"以 BottomSheet 说明"要不要在每节课前 10 分钟提醒你"，用户点同意才触发系统权限弹窗；被拒绝后设置页常驻一条可重新开启的说明行（含跳转系统设置的入口）；
   - **提醒设置页状态**：提前 N 分钟（默认 10）为全局设置，单课可覆盖（含"这门课不提醒"）；页面需覆盖九态中的 Empty（系统通知权限未授予时的引导态）、Disabled（课程已被移除/停课时的灰态）、Edge（节次跨午休/时间冲突时的提示）；
   - 文档已记录该界面的信息层级方向：提醒属于"设置域"，走设置页二级入口，**不占用主界面空间**。
5. **【补充·手动编辑界面】** 本次新增移交项：
   - **新增/编辑课程表单页**：承载 MVP 五功能之一的"手动编辑"，字段分组为三块——① 基本信息（课程名 / 教师 / 课程编号，编号可选）；② 时间（周次选择器、单双周、节次区间、星期）；③ 地点（教室）。**字段分组 ≤4 项/组**遵循工作记忆规则（见 §1 认知负荷基线）；
   - **周次选择器交互方向**：网格多选（1-20 周方格点选）+「全选 / 单周 / 双周 / 清除」四个快捷按钮，比输入框更不易错；选中周以主色填充方格（此处是"每屏 ≤2 处主色"纪律的例外场景——选择器的主色使用属功能性反馈，不算装饰）；
   - **节次区间**：起止节次用 Range 式选择（点击起点 → 点击终点），实时在表单顶部预览卡片外观；
   - **入口位置**：周视图 TopAppBar 的「+」（24dp 独立图标，Lucide `plus`）+ 空白格子长按快速新增（预填该格子的星期与节次）；
   - **编辑态与删除确认交互**：课程详情 BottomSheet 内提供「编辑」入口，跳转同一表单页（复用，不另做一套界面）；删除走二次确认（M3 AlertDialog，危险色按钮），确认文案写明影响范围（"将删除该课程全部 16 个周次安排"，而非笼统的"确定删除吗"）；
   - **状态覆盖**：本次表单页至少覆盖 Default / Focus / Error（字段校验：课程名必填、节次起止不越界、周次不得全空）/ Disabled（无周次选中时保存按钮灰化）/ Edge（超长课程名截断策略）五态。
6. 无障碍对比度验算表（两套主题 × 主要 Token 组合）。

**三轴刻度移交**：Variance=3 / Motion=3 / Density=7（见 §1）。

## 附：本方向文档的一页摘要（给赶时间的你）

| 决策项 | 结论 | 一句话理由 |
|---|---|---|
| 设计语言 | Material 3 + 动态取色 | 顺着 Compose 技术栈砍柴，动态色是 Android 的信任信号 |
| 对标 | Sleepy（技术路线）+ WakeUp（信息层级）+ 系统应用（终极形态） | 竞品已验证的路 + 最优的信息分层 |
| 色彩 | 双层系统：框架色走动态取色，课程色走固定 12 色黄金角调色板 | 课程颜色的身份稳定性 > 系统一致性 |
| 品牌 fallback 色 | Google Blue 体系深蓝（≈#0B57D0 系），非默认 Indigo | 蓝色=教育心智+校徽兼容+避开 AI 滥用色 |
| 深浅主题 | M3 light/darkColorScheme 双轨，深色是同等公民 | 用户夜间使用高频 |
| 中文正文 | 系统字体栈（不打包中文体）+ 自定义 Type Scale 锁层级 | 3-8MB 字体与轻量定位冲突；国产 ROM 字体已够好 |
| 数字 | Roboto Mono 等宽（Latin 子集） | 时间轴/周数对齐是驾驶舱纪律 |
| 图标 | **Lucide**（`icons-lucide-android:2.2.1`，MIT，24px 网格 / 2px 等宽描边），经 `AppIcons.kt` 门面引用，16/20/24dp | 与 M3 零摩擦的旧路线（material-icons）已被官方废弃冻结 1.7.8（ADR-002）；Lucide 单风格从结构上消除变体混用 |
| 周视图 | 左轴+7列同屏+sticky参照系+绝对定位架构+卡片2级信息+幽灵块显单双周 | 为"早八前10秒"设计 |
| 动效 | 全部 ≤300ms，跟手优先，尊重减弱动态设置 | 速度即美学 |
| 红线 | 无 emoji 图标 / 无紫粉渐变 / 无开屏 / 无占位文案 / 全走 Token | 详见 §10 |
