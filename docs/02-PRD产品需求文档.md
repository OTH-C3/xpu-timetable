## 0. 阅读指南（写给项目维护者）

这份文档回答四个问题：

1. **为什么做**——西工程大学生现在的课表方案差在哪（第 1-2 章）
2. **和谁竞争**——现有课表 App 的强弱与市场空白（第 3-4 章）
3. **做什么不做什么**——MVP 五项功能的优先级与明确不做清单（第 5-6 章）
4. **怎么算成功**——可验证的成功指标与验收标准（第 7-9 章）

> **原理说明：为什么 PRD 要先写「不做什么」？** 项目失败最常见的原因不是功能太少，而是功能太多导致每个都做不精。本项目的定位是「轻量、极快、极简」，每多一个功能都在侵蚀这个定位。所以第 6 章的 Out-of-Scope 清单和第 5 章的功能清单同等重要，甚至更重要。

## 1. 问题陈述

**谁**：西安工程大学在校本科生（金花校区 / 临潼校区），以及作为项目维护者的在校学生开发者。

**什么场景下遇到什么痛点**：

1. **官方渠道看课表体验极差**。学校 2026 年起教务全面迁移到「教育数字化应用服务平台」（一网通办 sz.xpu.edu.cn）+ 官方「西工程大」APP。但该官方 App 在 Apple App Store 的评分长期在 **1.3-1.7 分**（数百条评分），学生差评高度集中在：**「学生课表加载不出来」「想看个完整课表都看不了」「登录不上」「更新完白屏显示登录过期」「闪退」**。也就是说：学生**唯一官方授权的电子课表渠道，恰恰在课表这个最高频需求上最不可靠**。
2. **通用课表 App「适配层」失灵**。WakeUp、超级课程表等全国性产品的教务适配依赖各校教务系统的固定接口。西工程大 2026 年换用全新的一网通办平台后，这类 App 的「一键导入」对西工程大学生**已经失效或不可靠**（用户反馈形态：教务密码在官网能登录、在第三方 App 里就报密码错误——因为第三方模拟登录跟不上新版验证与登录流程）。
3. **通用产品的形态负担**。超级课程表等商业产品带开屏广告、信息流、社交模块；用户原话：「全都是广告，关闭广告后还要重新加载，不等个三四秒都进不去」。学生只想在赶去教室的路上 3 秒钟看一眼「下节课在哪」，却要付出等广告加载的代价。
4. **纸质课表 / 截图方案的信息衰减**。部分学生用拍照存截图或抄纸质课表应对。缺点：无法自动按周切换（西工程大有单双周课程，第 3 周和第 4 周的课不同）、无法提醒、换学期作废。

**现在怎么解决的**：忍受官方 App 的加载失败 + 截图/纸条辅助记忆 + 靠同学口口相传「下节课在哪个楼」。

**为什么不行**：课表查询是**每天多次、每次 3 秒**的高频微需求，当前所有方案要么慢（广告/加载），要么不可靠（官方 App 故障），要么不智能（截图不会按周切换、不会提醒）。这个「高频 × 高失败率」的组合就是本产品的立足点。

## 2. 目标用户与画像

### 2.1 主要画像 P1：西工程大普通本科生（核心用户，占目标用户 90%+）

| 维度 | 描述 |
|------|------|
| 年龄/年级 | 17-23 岁，大一到大四 |
| 校区 | 金花校区（市区，走读/通勤比例高）与临潼校区（郊区，课间跨楼移动时间紧） |
| 设备 | Android 手机为主（本 App 仅做 Android），主流国产 ROM（小米/OPPO/vivo/华为/荣耀） |
| 使用场景 A「课前 3 分钟」 | 赶去教室路上，需要 3 秒内确认「下节课是什么、在哪个楼哪个教室」——最高频场景，决定「冷启动即点即看」是 P0 需求 |
| 使用场景 B「周一早晨」 | 确认本周单双周课程上不上（西工程大普遍存在单双周排课） |
| 使用场景 C「开学第 1-2 周」 | 新学期导入课表，是**一年两次的黄金转化窗口**，导入失败 = 用户流失 |
| 使用场景 D「宿舍躺平时」 | 看明天/下周的课，规划时间 |
| 技术水平 | 会装 App、会用教务系统登录，**不一定会 sideload APK**（GitHub 下载 APK 对部分学生有门槛，安装引导必须在 README 和 App 内做好） |
| 对提醒的需求 | 课前提醒（默认提前 15 分钟），尤其新生和临潼校区学生（校区大、教室分散，需要预留走路时间） |

### 2.2 次要画像 P2：项目维护者本人（开发者兼用户）

- 编程经验有限，本项目同时是学习项目。对应需求：**教学级文档、清晰架构、可维护的解析器模块**（教务改版时只改一处）。
- 对产品的意义：项目维护者是最早的种子用户 + 校内传播节点（宿舍/班级口碑传播是校园 App 的第一增长曲线）。

### 2.3 反画像（明确不服务的对象）

- 需要跨校区课表聚合、社团活动管理、校园社交的学生 → 商业 App 与微信生态服务得更好，本项目不做。
- iOS 用户 → 本项目 MVP 仅 Android（技术栈 Kotlin，跨平台成本远超收益）。
- 教职工 / 研究生 → 课表数据源（一网通办「我的课表」）逻辑不同，MVP 不承诺支持。

## 3. 竞品分析

> **方法论说明**：调研遵循「直接竞品看强弱、替代方案看共存、差评看空白」三条线。差评来自应用商店公开评论与社区讨论。行业知识库中最接近的方法论基线为 SaaS-B2B 工具类（工具型产品的极简瑞士风、空状态引导、Onboarding、操作撤销等设计纪律），本 PRD 将其迁移应用至校园工具场景。

### 3.1 直接竞品（3+ 款）

| 竞品 | 形态 | 核心功能 | 优势 | 劣势（来自差评/公开信息） | 定价 |
|------|------|----------|------|--------------------------|------|
| **WakeUp 课程表**（wakeup.fun，闭源） | 全国通用课表 App | 教务导入（宣称 1800-3000+ 高校）、多课表、分享口令、桌面小组件、高度外观自定义、空教室查询、多端同步 | **体验标杆**：安装包体积极小（宣称竞品 1/10）、秒级启动即点即看、无广告口碑好、分享口令生态成熟 | ① 教务适配依赖固定接口，学校换新系统后**西工程大导入不可靠**（用户差评：「教务处官网我能登录，用你的链接就密码错误」）；② iOS 版口碑差（第三方统计评分 2.4-2.6）；③ 新版转向云同步账号体系，部分老用户不满「本地工具被迫上云」；④ 提醒功能被评「不够智能」 | 免费 |
| **Sleepy 课程表**（lingion/sleepy，开源，GPL） | 开源 Android 课表 | 教务直连（金智/强智/正方/URP）、多视图、桌面小组件、HSV 配色、本地优先默认不联网 | **定位最接近**：Kotlin + Compose + Material You、minSdk 26、数据全本地、凭据不落库、单校可申请适配（「让你的学校支持教务直连」） | ① 通用适配器优先服务主流教务系统，西工程大新平台（一网通办）不在其默认支持列表，需等待社区适配；② 更新节奏与单校需求脱钩（学校改版时只能催上游）；③ 版本迭代中曾出现网格视图、小组件刷新等回归 bug | 免费 |
| **Dawn Course 破晓课程表**（HF-CYGG/Dawn-Course，开源，GPL-3.0） | 开源 Android 课表 | WebView + JS 解析导入（新旧正方/强智/青果）、周/日视图、多学期、Glance 小组件、WebDAV 备份、脚本云端热更新、可选 LLM 兜底解析 | **架构参照**：证明了「WebView 授权登录 + 解析脚本」路线可行且可持续维护；脚本云端更新机制让教务改版时无需发版 | ① 依赖独立服务端仓库做脚本分发（与本项目「无后端」定位冲突，作反例）；② 多模块 Clean Architecture 对 MVP 阶段属过度设计；③ 项目规模小（社区活跃度有限），单校问题响应不确定 | 免费 |
| **超级课程表**（商业，对照品） | 全国通用校园 App | 课表 + 社区（下课聊/小纸条）+ 校园动态 + 广告变现 | 用户基数大、品牌知名度高 | 用户差评原话：「全都是广告，关闭广告后还要重新加载，不等个三四秒都进不去」「手机有一点晃动都会打开广告」；历史上多次开学季导入系统崩溃导致用户批量流失；工具被社交稀释，「下载就是为了课表，打开找不到课表」 | 免费+广告 |
| **课程格子**（商业，对照品） | 全国通用课表 App | 课表 + 社区导购/电台 + 课表格子内嵌广告 | 早期界面清爽、导入稳定（老教务时代） | 广告直接植入课表格子内（「打开课表就看见牛皮癣一样的广告」）；老教务适配同样随学校迁移失效 | 免费+广告 |

### 3.2 替代方案（学生今天真正在用的「竞品」）

| 替代方案 | 现状 | 为何没被完全替代 | 我们的切入点 |
|----------|------|------------------|--------------|
| **官方「西工程大」APP**（最直接的替代） | 学校官方出品，唯一带官方数据的渠道 | App Store 评分 1.3-1.7；差评高频词：课表加载不出来、登录不上、白屏、闪退、更新后登录过期 | 我们不替代它的全部功能（一卡通/办事），只把它**最失败的「课表」这一个功能做到极致**：离线秒开、永不转圈 |
| **纸质课表 / 课表截图 / Excel 表**（成本最低的替代） | 新生报到时学校/学长发放，学生拍照存相册 | 零成本、不会「系统故障」 | 不会按周切换（单双周）、不会提醒、查找慢；我们提供「导入一次、全年自动」 |

### 3.3 关键市场空白（差评暴露的机会）

综合差评，市场空白恰好是我们定位的四条：

1. **「适配空白」**：全国性产品的教务适配没有跟上西工程大的新平台，官方 App 又不可靠——**西工程大需要一个「只为这所学校优化」的课表工具**。这是单校 App 对抗大而全产品的唯一结构性优势：别人做 3000 所学校的平均分，我们做 1 所学校的 100 分。
2. **「速度空白」**：商业产品被广告拖慢（3-4 秒才能进课表），官方 App 被故障拖慢。即点即看始终是 WakeUp 口碑最好的点，也是我们要对齐的体验底线。
3. **「纯净空白」**：无广告、无社交、无推荐流，打开就是课表——对「只是想看个课表」的学生是稀缺品。
4. **「信任空白」**：WakeUp 转云、超级课程表要账号体系，学生日益警惕数据被收集。本地优先、零上传、开源可审计，是信任壁垒。

## 4. 我们的差异化定位

**一句话定位**：西工程大学生自己的、只为这一所学校优化的、即点即看的纯净课表。

**用户为什么选我们而不是竞品**——四个可验证的承诺：

1. **为西工程大而生**：导入路径直接对接 sz.xpu.edu.cn 一网通办（WebView 授权登录 + 课表接口解析），学校格式「课程名称(课程编号)(任课教师)(上课周,上课教室)」按西工程大真实数据结构原生解析。竞品的通用适配器做不到这个响应速度和准确度。
2. **比谁都快**：冷启动直接进课表页，目标 1 秒内可读（WakeUp 已验证小体积秒开在用户中口碑极佳，技术上我们以 R8 收缩 + Baseline Profile 对齐）。
3. **比谁都干净**：无广告、无社交、无推荐、无账号、无遥测；数据只存本机，凭据零存储零上传（开源 + README 隐私声明，可被任何学生审计）。
4. **坏了有人管**：GitHub 开源，学校教务改版时项目维护者自己就能修解析器（解析器独立模块，改版只改一处），不依赖任何外部公司的适配排期。

> **原理说明：为什么「单校优化」是护城河而不是劣势？** 通用课表 App 的成本结构决定了它必须服务尽可能多的学校，任何一个学校的适配问题都要排队。而本项目的目标用户只有一所学校的学生，维护成本与用户价值高度对称——这正是很多高校自发课表工具（复旦、吉大等校的社区脚本传统）长期存活的原因。放弃「通用」，换来「这一所学校的服务响应速度」，这笔交易对我们是纯赚。

## 5. 核心功能（RICE 排序）

> MVP 范围已由 Phase 0 锁定（教务导入 + 周视图展示 + 手动编辑 + 课前提醒 + 桌面小组件），本章只做**优先级排序与验收定义**，不扩张范围。
> RICE Score = (Reach × Impact × Confidence) / Effort。Reach 按「每学期受影响用户比例」估 1-10；Impact 按对单个用户的影响 0.25-3；Confidence 为确信度；Effort 估开发人月折算 1-10。

| # | 功能 | Reach | Impact | Confidence | Effort | Score | 里程碑 |
|---|------|-------|--------|------------|--------|-------|--------|
| 1 | **周视图课表展示**（打开即见、按周切换、单双周正确渲染、今日高亮） | 10 | 3 | 100% | 3 | **10.0** | M1（第一个可用闭环） |
| 2 | **手动编辑课程**（增/删/改课程，颜色、周次、教室、教师；含撤销） | 8 | 2 | 100% | 2 | **8.0** | M1 |
| 3 | **教务导入**（WebView 授权登录一网通办 + 拦截课表数据解析入库；兜底：WakeUp CSV / Excel / 手动） | 10 | 3 | 80% | 5 | **4.8** | M2（先做兜底导入，抓包确认接口后做直连） |
| 4 | **课前提醒**（默认提前 15 分钟通知，可调 5-30 分钟，按单双周与周次精准触发） | 9 | 2 | 80% | 3 | **4.8** | M2 |
| 5 | **桌面小组件**（今日课程列表小组件，不打开 App 即可看「下节课在哪」） | 9 | 2 | 80% | 3 | **4.8** | M3 |

**排序解读**：

- 周视图 + 手动编辑排最前（Score 10.0 / 8.0）：**这两项 + 兜底手动导入 = 没有教务直连也能用的完整产品**。先把「可用的最小闭环」立起来，教务直连（Score 4.8，Effort 最大、含抓包不确定性）作为第二阶段增强——这与上游文档 §5.4 的实施顺序结论一致：先 C+D（中间格式+手动）保证闭环，再做 A（WebView 直连）完成一键体验。
- 课前提醒与桌面小组件并列 4.8：提醒覆盖「怕迟到」场景（临潼校区课间移动距离长，刚需明确）；小组件覆盖「连 App 都懒得开」的场景，是即点即看体验的延伸。两者技术上都依赖「课表数据 + 周次计算」已就绪，故排 M2/M3。
- **为什么教务导入 Effort 最高（5）**：包含 WebView 会话管理、接口拦截、西工程大数据格式解析器、三套兜底格式适配，且有「接口结构未知需一次真实抓包」的不确定性。Confidence 只有 80% 的原因即在此。

## 6. 明确不做清单（Out-of-Scope）

> 每条附「为什么不做」。以下功能在 MVP 及可见的 v1.x 内均不实现，用户提了也先记录进 Backlog。

| 不做的事 | 为什么不做 |
|----------|-----------|
| 多课表管理（多套课表切换） | 单用户单学期只有一张主课表；多课表是「蹭课/辅修」小众场景，却使数据模型、UI、导入逻辑全面复杂化。v2 视用户反馈再议（Phase 0 已决议移出）。 |
| ICS 日历导出 | 学生系统日历使用率低，且导出格式转换（周次→日期展开）有大量边界细节；对核心体验零增益。v2 再议（Phase 0 已决议移出）。 |
| 云同步 / 账号体系 | 与「无后端、零上传、隐私零信任成本」定位正面冲突。WakeUp 转云引发的老用户反感是前车之鉴。本地数据 + 可选的本地备份文件导出即可覆盖换机需求（本地备份属实现细节，MVP 不承诺）。 |
| 社交 / 社区 / 下课聊 | 超级课程表用真实教训证明了「课表工具 + 社交」的失败：工具被稀释、用户为社交而来却忘了课表、内容治理成本失控。 |
| 广告 / 任何变现模块 | 「无广告」是差异化定位四大支柱之一，也是 WakeUp 口碑最好的点。为短期变现破坏定位 = 产品自杀。 |
| 成绩查询 / 空教室 / 校园卡等校园服务 | 官方 App 的领地，且每个都是独立的对接与合规负担。我们只做官方 App 最失败的那一件事。 |
| OCR 截图识别导入 | 识别错误率不可控、开发成本高，与手动编辑兜底重叠（Phase 0 已否决）。 |
| 验证码自动绕过（打码/OCR） | 合规红线；WebView 方案下由用户手动完成滑块，根本不需要。 |
| iOS / 鸿蒙 / 小程序版本 | 技术栈与维护带宽不支持；Android 是项目维护者与目标用户的主体平台。 |
| 多校适配 / 通用教务框架 | 「单校优化」是护城河；通用化会把我们变回 WakeUp 的排队适配模式。 |
| 应用市场上架 / F-Droid | 分发仅 GitHub Releases（Phase 0 已锁定）：零审核、零维护成本，匹配开源轻量定位。 |

## 7. 成功指标（可验证）

> 本项目无后端、无遥测，指标全部设计为**本地可测 / 仓库可统计 / 可人工验收**，不依赖任何数据上报设施。

| 类别 | 指标 | 目标值 | 验证方法 |
|------|------|--------|----------|
| 性能 | 冷启动到课表页可读 | **≤ 1s**（中端及以上机型） | 开发期用 `adb shell am start -W` + Macrobenchmark 实测，写入 README |
| 体积 | Release APK 体积 | **≤ 15MB**（争取 ≤ 10MB；WakeUp 已证明该量级可行，Sleepy 实测 13-20MB） | CI 构建产物体积检查，超标则构建失败 |
| 可靠性 | 教务导入成功率（含兜底路径） | **≥ 90%**（自己 + 帮同学实测，样本 ≥ 10 人） | 开学季实测记录；失败用例归档为 GitHub Issue |
| 正确性 | 周次/单双周渲染正确率 | 100%（用真实课表抽查第 1-18 周每周快照比对） | 自动化测试 + 人工抽查 |
| 稳定性 | 真机使用崩溃 | MVP 期内 0 次可复现崩溃 | 真机日常使用回归 |
| 采用 | GitHub Release 下载量 | 首学期 ≥ 100（宿舍/班级口碑传播量级），v1 发布 6 个月内 ≥ 500 | GitHub Release 统计 |
| 反馈 | 有效 GitHub Issue | 开学季 2 周内收到 ≥ 10 条真实用户反馈（导入问题/功能建议均算） | 仓库 Issue 统计 |
| 口碑 | 校内自发推荐 | 出现 ≥ 3 个「非项目维护者主动推广」的推荐场景（同学间互相安装、社群转发） | 项目维护者人工记录 |

> **原理说明：为什么不设 DAU/留存这类指标？** DAU/MAU 需要遥测上报才能统计，而「零上传」是本产品的信任底线，两者不可兼得。课表 App 的合理打开频率本来就低（每天 2-5 次、每次 3 秒），低频不等于低价值。因此用「下载量 + Issue 反馈 + 口碑」这类不需要侵犯隐私的代理指标衡量成功。

## 8. 验收标准（Given / When / Then）

### 8.1 周视图展示

- **GWT-1**：Given 已导入课表且当前处于学期第 N 周，When 用户冷启动 App，Then 直接呈现第 N 周周视图，当前时间之后的下一节课以醒目样式标记（「当前/下一节」高亮），整个呈现过程 ≤ 1s。
- **GWT-2**：Given 某课程只在上双周（如 2,4,6-16 周），When 用户切换到单周（如第 3 周），Then 该课程卡片不显示；When 切回双周，Then 卡片恢复显示。
- **GWT-3**：Given 一门课「1-8 周在 A 教室、9-16 周在 B 教室」（西工程大格式中同一课程多条记录），When 查看第 5 周与第 12 周，Then 分别显示对应教室。
- **GWT-4**：Given 用户横向滑动周视图，When 滑动跨周，Then 周次标题与日期同步更新；When 点击「回到本周」按钮（日历图标），Then 回到当前周。
- **GWT-5**：Given 未导入任何课程，When 打开 App，Then 显示空状态引导页（文案：「还没有课程，去导入你的课表」+「手动添加」两个入口按钮），绝不显示空白网格。

### 8.2 手动编辑

- **GWT-6**：Given 用户在周视图点击空白格子，When 点击后选择「添加课程」，Then 弹出课程编辑表单（课程名、教师、教室、周次、节次、颜色），保存后卡片立即出现在对应位置。
- **GWT-7**：Given 用户点击已有课程卡片，When 选择「编辑」并修改教室，Then 卡片信息更新；When 选择「删除」，Then 弹出二次确认，确认后卡片消失，并提供「撤销」操作（5 秒内可恢复，SaaS 工具型产品的标准撤销纪律）。
- **GWT-8**：Given 用户误操作删除课程，When 在 5 秒内点击撤销提示，Then 课程完整恢复（含颜色与周次设置）。
- **GWT-9**：Given 周次选择器，When 用户输入非常规格式（如「1-16 单周」），Then 正确解析为 1,3,5,7,9,11,13,15；When 输入非法格式（如「20」超出学期周数），Then 表单提示「超出学期总周数」并阻止保存。

### 8.3 教务导入

- **GWT-10**：Given 用户首次使用，When 在导入页选择「从一网通办导入」，Then App 内打开 WebView 加载 sz.xpu.edu.cn 登录页，用户自行完成账号密码与滑块验证（App 对输入过程零读取、零存储）。
- **GWT-11**：Given WebView 内已登录成功并进入「我的课表」页，When 课表数据接口返回，Then App 拦截并解析，弹出**导入预览**（显示解析出的课程数、总条数、疑似异常条目），用户确认后写入本地数据库。
- **GWT-12**：Given 解析器遇到无法识别的数据格式，When 导入失败，Then 明确提示「解析失败：教务系统可能已改版」，并**自动引导至兜底路径**（WakeUp CSV / Excel 导入 / 手动添加），绝不闪退、绝不丢失已拦截数据。
- **GWT-13**：Given 一条课程记录为「高等数学(080101)(张三)(1-16周,临潼校区A楼101)」格式，When 解析，Then 课程名=高等数学、教师=张三、周次=1-16、教室=临潼校区A楼101、课程编号=080101（编号存为元数据，不在卡片上主显示）。
- **GWT-14**：Given 用户重复导入同一学期课表，When 确认导入，Then 以覆盖方式更新本学期数据（导入前提示「将覆盖现有课表」），避免重复卡片。
- **GWT-15**：Given 教务系统校外不可达（未来可能限制校园网），When WebView 加载超时，Then 提示「无法连接学校服务器，请在校园网环境下重试或使用文件导入」。

### 8.4 课前提醒

- **GWT-16**：Given 用户开启提醒（默认提前 15 分钟），When 距下节课开始还有 15 分钟，Then 系统通知栏推送「高等数学 · 8:00 · 临潼校区A楼101」。
- **GWT-17**：Given 今日单双周课程不同，When 当天有课（双周课），Then 仅双周课触发提醒；When 当天该课因单周不上，Then 不推送该课提醒。
- **GWT-18**：Given 手机重启，When 重启后，Then 提醒计划自动恢复（无需用户重新打开 App——使用系统级 AlarmManager/WorkManager 保证，验收方式：重启手机后等待下一节课提醒）。
- **GWT-19**：Given 用户在设置中关闭提醒，When 到达原定提醒时间，Then 不再推送任何通知。
- **GWT-20**：Given 提醒推送后用户点击通知，When 点击，Then 直接打开 App 并定位到今日课程视图。

### 8.5 桌面小组件

- **GWT-21**：Given 用户在桌面添加「今日课程」小组件，When 当天有课，Then 小组件按时间顺序列出今日课程（课名、时间、教室）并高亮下一节。
- **GWT-22**：Given 用户在 App 内编辑/导入课程，When 保存完成，Then 小组件内容自动刷新（无需等下一次系统刷新周期）。
- **GWT-23**：Given 今日课程跨单双周（本单周无课），When 查看小组件，Then 显示「今天没有课」而不是列出双周课程。
- **GWT-24**：Given 用户未导入任何课程，When 查看小组件，Then 显示引导态「打开 App 导入课表」，不显示空白。

## 9. 边界条件与非功能需求

### 9.1 边界条件清单（开发与测试必须覆盖）

| 状态 | 场景 | 要求 |
|------|------|------|
| 空状态 | 无课程 / 无学期配置 | 空状态引导（见 GWT-5、GWT-24），引导导入或手动添加 |
| 错误状态 | WebView 加载失败 / 解析失败 / 文件格式错误 | 明确人话错误提示 + 自动引导兜底路径（见 GWT-12、GWT-15） |
| 学期边界 | 开学前（当前日期早于开学日）/ 学期结束 | 显示「未开学」/「本学期已结束」状态，不显示负数周次（竞品 Sleepy 曾出现负周数 bug，须引以为戒） |
| 节次边界 | 课程横跨午休/晚休分隔线；连排课（如 3-4 大节连排） | 卡片正确跨行渲染，不重叠、不错位 |
| 周次边界 | 周次输入 0 / 超 18 / 空串 / 「1-16周」带单位文字 | 表单校验，非法输入阻止保存并提示 |
| 时间边界 | 课程提醒时间点手机关机 | 开机后 AlarmManager 补偿策略：过期提醒不补发（避免开机轰炸），仅恢复未来提醒 |
| 数据边界 | 导入课表包含 0 门课（空学期）/ 40+ 门课（极端） | 空学期走空状态；大量课程时周视图滚动流畅不掉帧 |
| 删除保护 | 删除课程 | 二次确认 + 5 秒撤销（GWT-7/8） |
| 系统限制 | 应用被杀后台（国产 ROM 激进省电） | 提醒依赖系统级闹表机制（AlarmManager 转交系统调度）而非常驻进程；README 提供「允许自启动/后台权限」设置引导 |
| 权限拒绝 | 用户拒绝通知权限 | 课表功能完全不受影响；提醒功能入口显示权限缺失说明与系统设置跳转 |

### 9.2 非功能需求

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 冷启动进课表页 ≤ 1s；周视图滑动 60fps；APK ≤ 15MB；R8 minify + 资源收缩 + Baseline Profile | P0 |
| 隐私 | 凭据零存储零上传；无任何网络遥测/统计 SDK；仅教务导入时访问 sz.xpu.edu.cn；README 与 App 内「关于」页公开隐私声明 | P0 |
| 可用性 | 全功能离线可用（除导入环节本身需联网）；无任何单点在线依赖 | P0 |
| 稳定性 | 解析失败不崩溃（try-catch + 兜底引导）；导入失败绝不破坏已有本地数据（先写临时数据、确认后原子替换） | P0 |
| 兼容性 | minSdk 26（Android 8.0）至 targetSdk 36（Android 16）；主流国产 ROM（MIUI/ColorOS/OriginOS/EMUI/MagicOS）真机验证提醒与小组件 | P0 |
| 视觉 | Material 3 设计语言，界面极简；亮/暗色主题跟随系统；图标方案为统一 SVG 图标库（具体选型按项目依赖策略锁定，本 PRD 不预设）；**禁止紫色到粉色渐变的任何配色方案**；不使用 emoji 作为界面图标 | P0 |
| 文案 | 全中文真实文案，禁止任何占位文案；错误提示必须说人话（说清「发生了什么 + 怎么办」） | P1 |
| 可访问性 | 文本对比度满足基本可读标准；支持系统字体缩放；触控目标不小于 48dp | P2 |
| 国际化 | MVP 仅简体中文；代码层字符串资源集中管理（为未来预留，但不做翻译） | P2 |

### 9.3 数据埋点方案（本地版，适配「零上传」定位）

> **原理说明**：常规 PRD 要求接入统计 SDK 埋点（DAU、留存漏斗等），但本产品的信任根基是「零上传」，两者天然冲突。**决策：不做任何网络埋点**，改用以下零遥测的替代机制达成同等目的（对应第 7 章指标）：

| 常规埋点目的 | 本项目替代方案 |
|--------------|----------------|
| 注册/激活转化 | 导入成功首课表后，App 内温和提示「遇到问题？欢迎到 GitHub 提 Issue 帮助改进」（一次性、可关闭），把用户引导到可统计的公开反馈渠道 |
| 留存/使用频次 | 不统计。用 GitHub Release 下载量 + Issue 活跃度作为代理指标（见第 7 章） |
| 异常监控 | 本地错误日志（仅存本机，用户可一键复制并在自愿前提下粘贴到 GitHub Issue）；解析失败时自动生成「可复制的诊断信息」（脱敏，不含任何凭据），降低用户报障门槛 |
| 付费转化 | 不适用（无任何变现） |

**红线重申**：即使未来有商业化或增长诉求，也不得通过植入统计 SDK 突破「零上传」承诺——该承诺写入 README 与隐私声明后即构成对用户的公开契约，违反等同于产品失信。

## 10. 依赖与风险（产品视角）

| 风险 | 影响 | 缓解措施 | 责任人 |
|------|------|----------|--------|
| 「我的课表」接口结构未知，需一次真实抓包 | 教务直连（Score 4.8 项）无法开工 | 项目维护者配合提供一次登录后抓包；抓包前先交付「兜底导入 + 周视图」闭环，直连作为增强发布 | 项目维护者 |
