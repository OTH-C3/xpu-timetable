**硬件评估（针对本机 i5-12400F / 15 GiB RAM + zram / NVMe）：**
- Android Studio 本体 + Gradle 编译：可流畅运行，NVMe 缓解 I/O 瓶颈。
- Android 模拟器（AVD）：会额外占用 2–4 GB 内存，与 Gradle Daemon 并发时 15 GiB 总量偏紧。**收益保守评估：真机 USB/无线调试为首选（零额外内存开销、启动快），模拟器仅作无真机时的备选**——不做「必须上模拟器」的乐观推荐。
- 磁盘：AS + SDK + 模拟器镜像约占 10–15 GB，NVMe 954G 无压力。

## 4. 依赖管理方式

- **唯一事实源：`gradle/libs.versions.toml`**（Version Catalog），所有模块从 catalog 引用，禁止散落硬编码版本号。
- **轻量红线（与「轻量化」定位绑定）：**
  - 不引入 Firebase / 任何云端 SDK（无后端、无统计、无崩溃上报云端）；
  - 网络层仅 OkHttp（+ 可选 Retrofit 或 kotlinx.serialization 手写解析）；
  - 图片加载若无强需求不引 Coil（课表基本无网络图片）；
  - R8 minify + 资源收缩 + Baseline Profile（启动速度目标：冷启动进入课表页 < 1s，**待实测**）。
- **架构建议（Karpathy 纪律：反过度工程）：** MVP 单模块 + 分包（ui / data / domain / parser）起步；竞品 Dawn Course 的多模块 Clean Architecture 是规模化后的形态，MVP 阶段照抄属过度设计。等代码量上来再拆模块。

**Phase 1 已锁定选型（ADR 见 `docs/decisions/`；本表为速览，最终以架构文档为准）：**

| 用途 | 锁定选型 | 依据 / 说明 |
|------|----------|-------------|
| UI | Compose BOM 2026.08 + Material 3 | ADR-001 |
| 图标库 | Lucide（com.composables:icons-lucide-android:2.2.1，MIT） | ADR-002；全项目唯一一套，尺寸 16/20/24dp |
| 本地存储 | Room 3（课表数据）+ DataStore（偏好） | ADR-003 |
| 网络 | OkHttp 5 + kotlinx.serialization | ADR-005；不引入 Retrofit |
| 异步 | Coroutines + Flow | — |
| DI | 手动 DI（AppContainer） | ADR-004；不引入 Hilt / Koin |
| 导航 | Navigation 3 | ADR-008 |
| 架构形态 | 单模块 + 分层分包 | ADR-007；拒绝多模块 Clean Architecture |
| 桌面小组件 | Jetpack Glance | 架构文档 §9.4 |
| 提醒 | AlarmManager 精确定时 + WorkManager 兜底重试 | 架构文档 §8.4/§9.3；应对国产 ROM 杀后台 |

## 5. 教务系统对接分析（本项目最大技术风险点）

### 5.1 学校现状（2026-09-16 实测）

| 事实 | 来源/证据 |
|------|-----------|
| 学校已全面升级教务系统，集成进「教育数字化应用服务平台」（一网通办，统一身份认证），覆盖 PC 端网上办事大厅 + 移动端「西工程大」APP | 网信处官方服务页 nmc.xpu.edu.cn |
| 一网通办入口 `https://sz.xpu.edu.cn/`，登录方式：**账号密码 + 扫码登录 + 短信验证码**（账号=学号，初始密码=身份证后 6 位）；**校外 HTTPS 可直接访问**（本次实测可达） | 官网首页「一网通办」入口 + 登录页实测抓取 |
| 课表功能：「我的课表」，支持按课表类型/教学周/学年学期筛选；课程信息格式为 `课程名称(课程编号)(任课教师)(上课周,上课教室)` | 学校官方公众号「工程小事通」新生指引 |
| 老「教务处门户 jw.xpu.edu.cn」仍在（通知公告用），老教务系统 `jwxt.xpu.edu.cn` 标注校内网入口 `202.200.206.55`，**校外访问实测失败**；2026 年起教师端通知均引导走办事大厅 | 教务处通知 + 实测 |
| 无官方开放 API、无接口文档 | 全部公开渠道均无 |

### 5.2 可行路径对比

| 路径 | 原理 | 可行性 | 评价 |
|------|------|--------|------|
| **A. WebView 授权登录 + 解析（推荐主路径）** | App 内嵌 WebView 打开 sz.xpu.edu.cn，用户亲自完成登录（验证码/扫码/短信全部天然兼容），建立会话后拦截「我的课表」页面的 XHR/JSON 响应（或注入 JS 抓取 DOM），本地解析入库 | **高** | 凭据零接触零存储；登录环节永不失效（学校改版只需改解析器）；Sleepy 课程表对多校教务即用此类方案 |
| B. 纯 HTTP 模拟登录 | 逆向 SSO 登录流程，模拟提交账号密码 | 低-中 | 需处理可能的密码前端加密、验证码；每次学校改版全链路报废；**不做** |
| C. 中间格式导入（推荐兜底） | 解析 WakeUp 分享口令/CSV、Excel 模板、iCalendar(ICS) | **高** | WakeUp 生态成熟（各校学弟写适配脚本产出 CSV 屡见不鲜）；导入互操作性好 |
| D. 手动添加 | 手动录入课程 | 高 | 必须保留的最终兜底，同时保证纯离线可用 |
| E. OCR 课表截图 | 识别西工程大 APP 导出的课表图片 | 低 | 过度工程，识别错误率高，**不做** |

### 5.3 限制与风险（如实列出）

1. **无官方 API，接口随时变更**：开源课表社区反复验证过的教训——教务系统一升级，第三方导入即失效（复旦、吉大、南医大均有先例，催生一批过渡脚本）。缓解：解析器独立成模块（单一职责），改版时只改一处。
2. **课表接口的具体路径与响应结构未知**：SPA 页面接口无文档，需要一次真实账号 + 真机/浏览器抓包来确定（需要一次登录后的课表页抓包，或开发期自测）。
3. **凭据与隐私红线**：账号密码只在 WebView 会话内由用户亲自输入，App 不读取、不存储、不上传任何凭据；无后端、无遥测。这条写进 README 与隐私声明，也是开源社区信任的基础。
4. **不做验证码自动绕过**（OCR/打码平台）：合规红线，且 WebView 方案下根本不需要。
5. **校外访问当前可达但不保证永久**：若未来限制为校园网/VPN，导入功能需提示用户在校园网环境下操作（代码层面做好可达性检测与降级提示）。
6. **开源维护责任**：学校适配器需要跟随教务改版维护；README 需声明「非官方工具，与学校无关」。

### 5.4 推荐方案

**MVP 数据层 = A（WebView 直连）+ C（WakeUp CSV / Excel 导入）+ D（手动）三层兜底**。优先级：先做 C+D 保证 App 可用闭环，再做 A 完成「一键导入」体验（A 需要抓包确认接口后才可编码）。

## 6. 开源与交付

- 仓库：GitHub 公开仓库 + GitHub Actions CI（push 触发 lint/test/build，tag 触发 Release APK 自动构建签名）。
- 签名：签名密钥不入库（GitHub Secrets / 本地 keystore），CI 产物为未签名或 Release 签名 APK。
- License：**已定 GPL-3.0**（项目维护者 2026-09-16 决策）。协议全文已落 `LICENSE`（gnu.org 官方文本，674 行，sha256 `3972dc97…b36986`）。选它的理由：本项目核心资产是教务适配器代码，GPL-3.0 要求派生作品同样开源，保护未来社区适配贡献不被闭源白嫖；代价是不利于被闭源商业项目直接集成（已接受）。README 需声明「非官方工具，与学校无关」。
- README 必含：非官方声明、隐私声明（零存储零上传）、构建方法、适配状态。
